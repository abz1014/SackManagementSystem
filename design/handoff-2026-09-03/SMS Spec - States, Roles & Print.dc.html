IFL Sack Management System · states, roles, print

What the screens do when the data doesn't cooperate.

Part one speced the healthy screen. This part covers the other four fifths of the time: a request in flight, a request that failed, a period with nothing in it, a plant link that has gone quiet, and a screen being read by someone who is not allowed to change anything.

Paired with spec/app.css, which is the real stylesheet, and spec/HANDOFF.md.

Part one drew Setup as a five-tab screen. That is wrong. May say
  • The scale's verdict, always, named as the scale's.
  • The product's limits only when a product was in force at this reading's time.
  • On a sack, one line about cones weighed since the previous sack, with the caveat in the same sentence.
  • Provenance, behind a disclosure, for the one reader in a hundred who wants it.
May not say
  • Today's tolerance applied to a reading from weeks ago. The old app printed that difference and it meant nothing.
  • A cone count on a cone sheet — it would read as a packing list. The plant records no cone-to-sack link, and the count between two sacks has been measured from 0 to 254.
  • Merge keys, transform versions, source system names, collision ids.

Behaviour: Esc closes, the scrim closes, focus moves to the sheet on open and returns to the row on close. The sheet is display:none in print — a printed report must not carry whichever row happened to be open.

15

Every state

Five states, drawn at desk size. Each block polls independently, so a screen is routinely in two of these at once — the rule that follows from that is the important one: a block waiting on its own request keeps its own height, so the page never jumps as panels land.

Loading
.skel · named heights

A figure skeleton is --fs-display + --fs-body + 8px tall, not a guess — otherwise the page shifts 16px when the first panel arrives. No spinners anywhere: the shapes say what is coming.

Failed
.state.err + Retry

That did not load. The plant database may be unreachable from this machine.

The raw error goes to the console, never to the page. “Try again” refetches only the failed block.

One failed block never blanks the screen. If Attention fails, the figures above it still stand — they came from a different request.

Empty
Empty · one sentence, no art
Readings

Nothing was recorded in this period.

The line may not have run. Try the whole day

An empty period is a normal fact on a plant that runs six days. It gets a sentence and a way out, never an illustration and never “No data available”.

Stale & late
.strip.alarm · measured, not assumed
{{ h.text }}

Cadence and the stale threshold both come from /api/live — they are measured from sync history, not hardcoded. When stale, the headline stops asserting a state and the pulse stops. Motion ceasing reads faster than a colour change.

Replay
.replay · the second ink band, and the only other one
Showing the line as it stood at 09:40 on 28 August 2026. This is not live. Return to now

Ink, full width, above the bar — the only element allowed to sit above the app's own chrome, because it changes the meaning of every number below it.

The pulse does not run in replay. Nothing is arriving, so nothing should look like it is.

The verdict mark, on paper

On screen it is an ink fill. In print it becomes a rule and ink text — because browsers drop background graphics by default, and the person printing does not know that setting exists. Same content, same authority, no dependency on a checkbox.

What the print header carries

Line, period, shift, coverage, newest reading, who printed it and when. The screen chrome would otherwise take all of it away, leaving a page of numbers that is undated and unattributed — and therefore worthless as a record.

Dropped in print
  • Bar, strip, replay band, sheet, scrim, wall.
  • Station bars — empty boxes on paper; the numbers carry the fact.
  • Skeletons, hover readouts, every .no-print.
  • The hanging label: blocks go back to label-above-content.

Rows and blocks carry break-inside: avoid, so a shift never splits across two sheets. Colour survives: the accent is 6.82:1 and prints legibly in greyscale.

Never names the field

“That username and password did not match.” Saying which one was wrong turns the form into a way to confirm that an account exists.

Lockout is stated in minutes

Eight failures in fifteen minutes locks that client out for fifteen. The server returns the seconds remaining, so the form says a number rather than “try again later”.

The wall must never see this screen

Sessions renew once past half their seven-day life, so a display that polls all week never expires. If the wall ever shows a login form, that is a bug in session renewal, not a thing to design for.

Weight — the second chart, and the adjustment log

Distribution is the second position on a toggle, never the default. A distribution tells you the spread; it cannot tell you that weight stepped up at 09:40 after a doff, which is the thing an engineer fixes during a shift.

Bins beyond a limit take the accent fill; everything inside is graphite, and hover turns one bin ink. The readout is a line of text above the chart, right-aligned — never a floating tooltip, which covers the marks it describes, cannot be read from a wall, and does not exist for a keyboard.

The three reference labels sit in a band above the plot, and that is a correction. Weight.tsx draws them in-SVG at y={T + 11} while a bar may reach y={T}, so whether a label is readable depends on the bin heights of the day. Give the plot a 22px top inset and hang the labels off it: lower limit right-aligned to its rule, target and upper left-aligned. The same fix applies to the Over time chart's RefLine labels, which can collide with the line they annotate.

Four roles

Read off auth.ts and the route table in app.rbac.test.ts, not invented. Ranks are numeric and gates are >=, so every higher role inherits everything below it.

Every role sees every screen and every number. Roles gate writes and two exports — never visibility. That is the design rule: an operator who cannot see the reject rate cannot act on it.

Hidden, not disabled

A control a role can never use is absent, not greyed. A disabled button is a promise the app will not keep. The one exception is the period control, where a disabled button means “no data for that range”, which is a fact about the data rather than about the reader.

The gear is the only nav change

Setup is admin-only and lives behind the gear, so the nav is identical for the other three roles. Sync health, the one block in Setup everybody needs, is reachable from the strip's lag sentence regardless of role.

A 403 is a bug, not a state

If the UI hides what a role cannot do, a 403 can only mean the client and the server disagree. It gets the generic failed state and a console error — never a designed “you don't have permission” screen, which would only ever be seen because of a mistake.
