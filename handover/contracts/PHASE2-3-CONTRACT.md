## Phase 2 — sync-worker (`sms/sync-worker`, `sms/cli`)
1. **Adapter interface** `sync-worker/src/reader/SourceAdapter.ts`:
   ```ts
   export interface SourceAdapter {
     readonly systemCode: string;               // 'ifl_sql'
     readonly def: IflTableDef;
     probe(): Promise<{ ok: true; roundTripMs: number } | { ok: false; error: string; classification: ErrorClass }>;
     sourceEpoch(): Promise<string | null>;     // create_date key
     fingerprint(): Promise<string>;
     columnList(): Promise<string[]>;           // full "name type" list, ordinal order
     maxSourceId(): Promise<number | null>;
     readSince(afterId: number): Promise<Record<string, unknown>[]>;
   }
   export type ErrorClass = 'transient' | 'auth' | 'schema' | 'unknown';
   export function classifyError(err: unknown): ErrorClass;   // mssql: ESOCKET/ETIMEOUT/ECONNRESET/ECONNCLOSED → transient; ELOGIN, error numbers 18456/229/230/297 → auth; 207/208/4060 → schema; else unknown
   export function createAdapter(systemCode: string, pool: ConnectionPool, def: IflTableDef): SourceAdapter; // registry: 'ifl_sql' → IflSqlAdapter; anything else throws `No adapter is registered for source system "<x>"` (the PLC/OPC adapter is deliberately not built — roadmap Phase 2B)
   ```
   `IflSqlAdapter implements SourceAdapter`. `runner.ts`, `epoch.ts` and the CLI use `createAdapter(def.systemCode, ...)`, never `new IflSqlAdapter` directly (tests may).
2. **Retry with classification**: `util/retry.ts` gains `{ retryOn?: (err) => boolean }`; the runner retries only `transient` errors (auth/schema failures halt immediately with the classification in the halt row's error_text — retrying a permissions failure four times with backoff was the old behaviour). Wrap the IFL pool connect in `index.ts`/`context.ts` with the same policy (3 attempts, transient only).
3. **Per-table isolation**: `runOnce` no longer aborts the pass on the first halted table. Each table's halt writes its own `sync_run` row (outcome 'halted', as today) and the loop continues; at the end, if any table halted, throw one `AggregateError`-style Error whose message lists each halted table and reason (so the worker log shows it and the CLI exits 1), AFTER the healthy tables' rows were written. The transform still runs for the tables that succeeded (pipeline.ts: run transform when at least one table succeeded; record the aggregate error afterwards).
4. **Column-list drift (non-fatal)**: on epoch resolution, read `columnList()`; if the epoch row's `column_list` is NULL, store it (UPDATE sms.source_epoch SET column_list = @json WHERE epoch_id = @id); else compare — on difference raise dq finding `source_columns_changed` (WARNING, subject_table = raw short name, detail = `columns added: [...]; removed: [...] on <source_table> (generation <id>) — the fingerprint of the columns SMS reads is unchanged, so ingestion continues; review whether SMS should read the new columns`). Dedup by detail.
5. **Connection probe recorded**: at the start of each pass, `probe()` the acquisition source once (a `SELECT 1` on the IFL pool + `SELECT COUNT(*) FROM sys.tables`); a failed probe writes the pass-level halt rows (existing `recordHaltedPass`) with the classification. The probe's round-trip is logged in the pass summary JSON (`sourceProbeMs`).
6. **Structured logging** without a dependency: `shared/src/log.ts` exporting `createLogger(svc: string)` → `{ info(msg, extra?), warn(...), error(...), child(extra) }` writing one JSON line per event to stdout (`ts, level, svc, msg, ...extra`), with a `correlationId` field when the child carries one (the worker's pass `runId`). The worker's existing inline `log()` in index.ts moves to it; the retry warning and lock messages use it; the CLI keeps its human-readable output (interactive tool) but errors go through the logger too. The API's access log and 500 handler use `createLogger('api')` (API agent).
7. `TRANSFORM_VERSION` → **2** in `shared/src/domain/version.ts` with a comment listing what changed since 1 (attribution from MaterialId, `night_belongs_to` stamped, `source_epoch`, shift boundaries from the rule, `ingested_at_utc`/`ingest_run_id` provenance, reject attribution). The transform stamps 2; `rebuild` restamps.
8. Tests: classifyError; retry skips non-transient; createAdapter registry throws for unknown code; per-table isolation (table 1 halts, table 2 still written, aggregate thrown after); column-list stored then compared → finding; probe failure → pass-level halt rows; logger output shape (one JSON line, correlationId present).

## Phase 3 — canonical model (`sms/shared`, `sms/sync-worker`, `sms/api`, `sms/web`)
1. **Replace the dead contract**: `shared/src/domain/events.ts` (14 exports, zero importers, wrong `AttributionMethod` union) becomes the REAL canonical record contracts — `shared/src/domain/canonical.ts` exporting interfaces that mirror the tables column-for-column: `ConeReading`, `SackReading`, `RejectEvent`, `ProductRecord`, `ProductLimitVersion`, `Machine`, `Station`, `ShiftRule`, `CalibrationAdjustment`, `DataQualityEvent`, `AuditEvent`, plus `AttributionMethod = 'none' | 'source_column' | 'manual_entry'`, `AttributionConfidence = 'high' | 'low' | 'ambiguous'`, `SourceSystem = string` (configured, not a union), and a `Provenance` interface (`sourceSystem, sourceEpoch, sourceRowId, sourceTsUtc (IFL insert), productionTsUtcMs, ingestedAtUtc, ingestRunId, rawId, transformVersion, attributionMethod, attributionConfidence`). `events.ts` is deleted and `shared/src/index.ts` exports `canonical.ts`. The transform's row builders in `transform.ts` are typed against `ConeReading`/`SackReading`/`RejectEvent` (so a drift is a compile error — the thing events.ts falsely claimed).
2. **Transform writes provenance**: `ingested_at_utc` = raw `read_at_utc`; `ingest_run_id` = raw `ingest_run_id`; reject rows get `attribution_method`/`attribution_confidence` by the same rule as cones (`'source_column'`/`'high'` when `src_MaterialId` is present, else `'none'`/`'low'`); `persistCanonical.ts` column lists updated.
3. **`dq_finding.subject_ref` written** wherever a finding concerns one row: stale/future timestamp, impossible weight, station_not_in_roster → the raw_id of the first offending row (the count stays in `count`). `persistFindings` takes an optional `subject_ref`.
4. **Lineage reachable by a person** (API + web): the register row payload (`api/src/services/register.ts`) and the reading-sheet endpoint gain a `provenance` object: `{ sourceSystem, sourceTable, epochLabel, sourceRowId, rawId, sourceInsertUtc (ingest_ts_utc), ingestedAtUtc, ingestRunId, transformVersion, attributionMethod, attributionConfidence, nightBelongsTo }`. `web/src/screens/ReadingSheet.tsx` renders a **Provenance** block at the bottom (plain words in words.ts: "Where this reading came from"): source table · generation · source row id · read into SMS at · transform version · how the product was determined). The epoch label was on Setup only; it now sits next to `source_row_id`, which names two rows since 5 Aug 2026.
5. **Rebuild gate**: `cli/src/commands/rebuild.ts` `--snapshot-id` must match `/^[A-Za-z0-9][A-Za-z0-9_.:\\-]{7,}$/` AND the command refuses to run while a worker pass is in progress (`SELECT COUNT(*) FROM sms.sync_run WHERE finished_at_utc IS NULL` > 0) — the lock already covers the transform, this covers the reader. The audit row records the snapshot id as given.
6. **Data dictionary**: `sms/scripts/data-dictionary.mjs` reads `INFORMATION_SCHEMA.COLUMNS` + `sys.extended_properties` (none today) from the app DB (env from .env, same loader as migrate.mjs) and a hand-written description map `sms/db/dictionary.json` (`{ "sms.cone_event": { "_table": "...", "column": "description", ... } }`) and writes `DATA-DICTIONARY.md` at the repo root: one section per table (31 + the new ones), columns with type/nullability/default/description, and a "Provenance chain" section explaining raw → canonical → sync_run → source_epoch. Descriptions for every column of the three canonical tables, the four raw tables, source_epoch, sync_run, dq_finding, audit_log, product_limit_version, product, station, machine, line, shift/weight/plausibility rules, reject_code (the rest may say "see migration NNN"). `npm run dictionary` script in sms/package.json.
7. Tests: canonical types compile against the transform (a type-level test file that assigns a built row to `ConeReading`); attribution() for `'source_column'` vs `'none'` on cones AND rejects; `subject_ref` present on a stale-timestamp finding; the register payload includes `provenance` with the joined epoch label; rebuild refuses a bad snapshot id and a running pass.
