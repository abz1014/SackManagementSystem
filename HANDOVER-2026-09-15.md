## 6. The PDAS procedure and what SMS must do

Source: field notes outside the repo (`Desktop\SPS unzip\SPS\*.jpg`,
`Desktop\P-DAS Program (2).xlsx`, the `nhs_events` log of the local
`PDAS_TP1U2_SEP07` copy, `Desktop\IFL_SMS_Pdas_Process_And_QCS_Explanation.docx`).
The engineer's own SOP, "QCS ID Creation by P-DAS", run by hand today in
SSMS:

1. `GetAllBlends` / `GetAllCounts` / `GetAllTubeTypes` / `GetAllMaterials` —
   look up what exists.
2. `AddBlend` / `AddCount` / `AddTubeType` when the needed one is missing
   (used 9/13/26 times respectively in the observed log).
3. `CreateMaterial(blendId, countId, tubeTypeId, setpoint 1960, WT+ 30,
   WT− 30, active 1, Desc1 = lot name, Desc2 = PP colour)` — note the
   returned Material ID.
4. `CreatePallet(materialId, packSchemaId 1, lot, palletActive,
   PalletDesc1 = sack colour)` — refuses a duplicate (material, schema,
   lot) with error `-8001`. Note the returned Pallet ID.
5. "New ID will be shown in QCS panel."

**How a machine actually gets a product's limits:** the QCS panel lists
active materials and pallets (`funcGetArray MATERIAL`/`PALLET`); the
**operator** selects them on the machine's own panel
(`funcGetConeId`/`funcGetPalletId`); the panel then fetches that material's
setpoint and offsets **at that moment** (`FuncGetConeWeight`). Limits reach
a machine only when the operator (re)selects on the panel — **SMS never
selects on the machine, and there is no PLC path.** This is the answer to
the open question in §5: today, a changeover declared in SMS is a reporting
record only, unless the panel independently reads PDAS's active flag on its

## 10. Rules not to undo

From `CLAUDE.md`'s "Rules the code now enforces" (the 3 Sep 2026 redesign),
each cited by the file where it lives, each existing because it was a real,
previously-shipped defect:

1. **One status vocabulary.** The scale's own in-range bit is the single
   flag, named as the scale's; the product's tolerance is a second,
   separately-named fact shown only when a product was in force at that
   reading's own time. `api/src/services/productAt.ts`. The old app applied
   today's tolerance to readings weeks old.
2. **Two clocks, named.** `api/src/services/plantClock.ts`. Production
   timestamps are the plant's wall clock labelled UTC; app-written instants
   are genuine UTC — five hours apart on this plant. **Under strain in the
   audit (H7):** the cross-check that would catch a mismatched host
   timezone is commented out in `.env.example` and absent from the sync
   worker entirely.
3. **The detectors ignore the period.** Station drift, the attention list,
   and reject episodes run over a fixed 14 production days
   (`web/src/lib/period.ts` `trailingWindow`) because the pattern tests need
   consecutive days.
4. **The health decision is server-side and measured.** `live.ts` reports
   freshness from the *oldest* source table, not the newest, and states the
   measured lag. No screen asserts whether the line is running when health
   is not `ok`.
5. **No over-claiming.** No station-level correction advice from weighing
   data alone; no product limits without a product; the Weight headline
   states mean and target as two facts.
6. **One station table**, on Weight, showing bias against both the line and
   the target.

**Plus, not in that numbered list but equally load-bearing:**
- **The 18-minute acquisition-lag lesson.** This software never sees the
  present — IFL's acquisition layer writes a cone's row ~18 minutes after
  it is weighed. Every "recent" window must be anchored on the newest
  *reading*, never on `Date.now()`. Fixed in `api/src/services/live.ts`;
  three regression tests lock it down.
- **The epoch halt rule.** An unknown source generation halts ingestion
  rather than guessing (`sync-worker/src/epoch.ts`). `sms epoch:accept`
  registers a new generation — never automatic. (The recovery path for a
  fingerprint-only drift is currently broken — audit H3/#10 — but the halt
  behaviour itself is correct and must not be relaxed.)
- **The one-audience rule.** Every screen is open to every signed-in
  account; only Setup is rank-gated. Roles gate writes only. Do not
  reintroduce a read-access tier — this was tried on 2 Sep 2026, confirmed
  wrong by IFL's own representative the same day, and reverted.
